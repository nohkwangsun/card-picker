# card-picker — 신용카드 혜택 매니저

조사한 신용카드/체크카드 혜택 엑셀을 구조화된 JSON으로 만들고, 소비 패턴을 입력하면
카드별 예상 혜택 금액을 계산해 랭킹으로 보여주는 정적 HTML 도구입니다.

🔗 **바로 쓰기**: https://nohkwangsun.github.io/card-picker/
(GitHub Pages가 `main` 브랜치를 서빙하도록 설정되어 있다는 전제입니다 — 안 열리면
저장소 Settings → Pages에서 Source가 `main` / `/(root)`로 되어있는지 확인해주세요.)

## 구성

```
data/
  cards_raw.json      카드 비교 xlsx 원문을 기계적으로 그대로 옮긴 것 (참고/디버깅용, 앱은 안 씀)
  benefit_tags.json   카테고리 계층 + 혜택 매핑 + 카드 기본정보가 전부 합쳐진 최종 데이터
  cards.json          benefit_tags.json에 카드 id를 붙인 배열 형태 (index.html에 그대로 내장됨)
scripts/
  xlsx_to_raw.py          카드 비교 xlsx -> data/cards_raw.json (참고용 원문 추출)
  import_from_mapping.py  카테고리·혜택매핑 xlsx + 카드 비교 xlsx -> data/benefit_tags.json (핵심 파이프라인)
  build.py                data/benefit_tags.json -> data/cards.json, index.html에 주입
index.html            혜택 계산기 앱 (데이터가 내장된 단일 파일, 더블클릭으로 바로 실행)
```

## 화면 구성

- **카드 비교**: 필터/검색, 테이블 또는 "전체 펼쳐보기"
- **혜택 계산기**: 4단계 접이식 섹션 — ① 월 소비 입력(쓰는 카테고리만 추가) + 마일리지/포인트
  환산가치 설정, ② 우선순위(선택), ③ 카드 1장 랭킹, ④ 카드 조합 추천. ①③은 기본으로
  펼쳐져 있고 ②④는 접혀 있습니다 (우선순위를 추가하면 ②는 자동으로 펼쳐집니다).
- **카드 상세**: 카드 하나를 골라 구조화된 혜택 + 엑셀 원문을 봅니다.
- **⚙ (우측 상단)**: **JSON 직접 편집**(카드/혜택 데이터를 텍스트로 직접 고치고 적용/다운로드),
  브라우저 저장 데이터(소비 입력값/우선순위/환산가치 설정 + JSON 편집 내용) 초기화.

## 데이터 갱신 방법

카테고리 221개 · 혜택 282개 항목 정도로 데이터가 많아진 뒤로는, xlsx를 통째로 갱신하기보다
**⚙ 탭의 "JSON 직접 편집"에서 필요한 카드/혜택만 바로 고치는 게 기본 방법**입니다.

1. ⚙ 탭을 열면 현재 데이터(categories/rewardPrograms/cards)가 JSON 텍스트로 표시됩니다.
2. 필요한 부분만 고친 뒤 "적용"을 누르면 이 페이지에 바로 반영됩니다 (이 브라우저의
   localStorage에 저장되어 새로고침해도 유지되지만, 다른 기기·브라우저에는 남지 않습니다).
   JSON이 잘못되면 어느 줄 근처가 문제인지 메시지로 알려줍니다.
3. "다운로드"로 받은 `cards.json`을 저장소의 `data/cards.json`으로 교체하고 커밋하면
   영구 반영됩니다 (index.html에는 `scripts/build.py`로 다시 주입해야 실제 배포에 반영됨 —
   `build.py`가 `data/benefit_tags.json`을 읽어 주입하므로, `cards.json`만 손으로 고쳤다면
   `data/benefit_tags.json`도 같은 내용으로 맞춰주거나 build.py 없이 index.html의
   `<script id="card-data">` 블록을 직접 교체해야 합니다).

각 카드 항목의 형식은 `data/cards.json`을 참고하세요 (`id`/`name`/`issuer`/`group`/`annualFee`/
`familyCardFee`/`raw`/`benefits[]`). `benefits[]`의 각 항목은 `code`(카테고리 코드)·`type`·
`rate`또는`amount`·`cap`·`capGroup`·`selectGroup`·`minCardSpend`·`rewardProgram` 등을 가지며,
자세한 의미는 아래 "카테고리 체계"와 "혜택 매칭 방식" 절을 참고하세요.

카테고리 체계 자체를 바꾸거나 카드가 한꺼번에 많이 추가/변경될 때는 원본 xlsx 파이프라인을
다시 씁니다.

1. **카테고리·혜택매핑 xlsx** (안내/카테고리/혜택매핑/혜택유형·조건/변경내역 5개 시트) —
   카테고리 코드 체계와 카드별 혜택 문장이 카테고리 코드 단위로 쪼개져 있는 원본.
2. **카드 비교 xlsx** — 카드사/연회비/가족카드 등 기본정보. A열에 `카드사`라는 라벨이 있는
   행을 기준으로 카드 이름 행을 자동 인식하므로, 그룹 행이 있든 없든 레이아웃이 크게
   바뀌어도 대응됩니다.

```bash
python3 scripts/import_from_mapping.py 카테고리매핑.xlsx 카드비교.xlsx   # data/benefit_tags.json 갱신
python3 scripts/build.py                                                 # data/cards.json 재생성 + index.html에 주입
```

이 파이프라인을 다시 돌리면 `data/benefit_tags.json`이 통째로 덮어써지므로, JSON 직접
편집으로 먼저 손댄 내용이 있다면 xlsx 쪽에도 같이 반영해두지 않으면 덮어써져 사라집니다.

`scripts/xlsx_to_raw.py 카드비교.xlsx`는 참고용으로 `data/cards_raw.json`(기계적 원문
추출본)을 별도로 갱신할 때 씁니다. 계산기 자체는 `data/cards_raw.json`을 읽지 않습니다.

## 카테고리 체계 (계층형 코드)

`data/benefit_tags.json`의 `categories`는 코드 기반 계층 구조입니다 (예: `17-01-01` =
주유·충전 > 주유소 > GS칼텍스, 총 221개). 각 카테고리는 `group`/`level`/`kind` 속성을
가지며, `kind`는 세 종류입니다.

- **사용처**: 실제 지출 카테고리 (소비 계산기에 입력하는 대상). `01 국내 전가맹점` /
  `02 해외`가 포괄 카테고리이고, `03`~`31`은 마트/편의점/카페/주유/여행 등 구체적인
  가맹점·업종별 카테고리입니다.
- **서비스**: 라운지/발레파킹/호텔·렌트카 멤버십/연간 바우처/브랜드 서비스 등 지출과
  무관한 혜택. 계산기의 "우선순위(금액 외 기준)"와 카드 상세에 반영됩니다.
- **결제수단**: 네이버페이/카카오페이/삼성페이 등 간편결제. 다른 사용처 카테고리와
  겹칠 수 있으므로(예: 편의점에서 삼성페이 결제), 같은 소비를 두 카테고리에 동시에
  입력하면 실제보다 혜택이 과대 계산될 수 있습니다 — 겹치지 않게 입력하세요.

## 혜택 매칭 방식 — 카테고리 계층으로 "브랜드 한정 혜택" 문제 해결

카드의 각 혜택은 카테고리 코드 하나에 매핑되어 있습니다. 사용자가 입력한 소비
카테고리 코드가 그 혜택 코드와 **같거나 더 구체적인 하위 코드**일 때만 그 혜택이
적용됩니다. 예를 들어 "GS칼텍스"(`17-01-01`)에 지출을 입력하면 "주유소"(`17-01`) 전체
혜택도, GS칼텍스 전용 혜택도 매칭 후보가 되고 이 중 **더 구체적인 쪽이 우선**합니다.
반대로 "주유소"라는 상위 카테고리에만 입력하면 GS칼텍스 전용 혜택은 매칭되지
않습니다(어느 주유소인지 모르므로). "01 국내 전가맹점"은 예외적으로 해외(02) 트리를
제외한 모든 사용처 카테고리에 대해 매칭되는 포괄 카테고리로, 항상 더 구체적인
혜택보다 낮은 우선순위를 갖습니다.

이 방식이 과거의 "브랜드 한정 혜택" 특수 처리(진에어 전용 할인이 항공권 전체에
잘못 매칭되던 문제)를 대체합니다 — 이제는 카테고리를 얼마나 구체적으로 입력하는지에
따라 자연스럽게 정확한 혜택만 매칭됩니다. 같은 카드가 한 카테고리에 대해 같은
깊이의 혜택을 여러 개 가지고 있으면(예: 평일/주말 구분) 합산되고, `택1`(선택그룹)로
묶인 혜택은 그중 가장 유리한 하나만 반영됩니다. 여러 카테고리가 한 한도를 공유하는
혜택(예: 여러 가맹점이 월 한도 하나를 나눠 쓰는 경우)은 합산 후 한 번만 한도를
적용합니다.

## 혜택 유형

`discount`(청구할인) · `fixedDiscount`(정액할인) · `perLiterDiscount`(리터당 할인,
평균 유가 1,700원/L 가정으로 %를 근사) · `accrual`(포인트적립) · `mileage`(마일리지적립) ·
`feeDiscount`(수수료할인) · `perTxCashback`(건당 정액 캐시백, 월 1회 발생한다고 가정하는
근사치) · `voucher`(연간 1회성 바우처, 연회비처럼 12개월로 나눠 반영 — 카테고리 매칭과
무관하게 카드 전체 사용액이 조건을 채우면 적용) · `freeUse`(라운지/발레파킹 등 무료
이용 횟수, 금액이 아닌 "우선순위" 기준으로만 반영) · `serviceOnly`(Visa Infinite 등
카드 네트워크 자체 서비스, 서술 정보만 표시).

## 마일리지/포인트 환산가치

카드마다 적립처가 다른 마일리지/포인트(대한항공 스카이패스, 현대 M포인트, Amex MR,
마이신한포인트, KB포인트리, 네이버페이 포인트 등)를 계산기의 "① 월 소비 입력" 아래
"마일리지/포인트 환산가치 설정"에서 각자 원하는 원화 환산가치로 조정할 수 있습니다.
적립처가 특정되지 않은 항목은 "기타 마일리지"(기본 20원) / "기타 포인트"(기본 1원)
값을 씁니다. 설정은 이 브라우저에 저장됩니다.

## 계산 방식에 대한 주의

- 원문 문장이 카드마다 제각각이라 여러 곳에서 근사치를 씁니다: 정액/건당 캐시백은
  "월 1회 발생"으로 가정, 리터당 할인은 평균 유가로 %를 근사, 구간형 조건(전월실적/
  한도)은 가장 낮은 구간을 보수적으로 적용, "면제"라고만 적혀있고 구체적 수수료율이
  없는 수수료 할인은 1%로 근사합니다. 정확한 조건은 항상 "카드 상세" 탭의 원문을
  확인하세요.
- 각 혜택 항목의 `minCardSpend`는 "이 카드 자체의 월 총 사용액"이 얼마 이상이어야
  그 혜택이 활성화되는지(전월실적 조건을 숫자로 옮긴 것)를 나타냅니다. 카테고리
  지출액이 아니라 그 카드에 실제로 몰아준 총액 기준입니다.
- 이번 카드 비교 xlsx는 카드 그룹(프리미엄/일상/마일리지) 행이 없는 레이아웃이라,
  모든 카드가 "기타" 배지로 표시됩니다. 그룹 구분을 다시 보고 싶으면 원본 xlsx에
  그룹 행을 추가해서 전달해주세요.

## 혜택 계산기 — 우선순위 (금액 외 기준)

**혜택 계산기** 탭, "카드 1장만 쓴다면" 랭킹 위에 "+ 우선순위 추가"가 있습니다. 라운지
이용 횟수/마일리지 적립 여부/발레파킹 횟수/공항 리무진·철도 이용 횟수/호텔·렌트카
멤버십 보유/연회비(낮은 순) 중에서 기준을 순서대로 추가하면, 랭킹이 금액(순혜택)보다
이 기준들을 먼저 따져서 정렬합니다 (1순위가 같으면 2순위로, 모두 같으면 그때
금액순). 숫자 기준에는 "최소값"을 넣어 조건 충족 여부 배지도 같이 볼 수 있습니다.
(카드 조합 추천에는 아직 반영되지 않고, 단일 카드 랭킹에만 적용됩니다.)

## 혜택 계산기 — 랭킹과 조합 추천의 차이

- **카드 1장만 쓴다면 (랭킹)**: 모든 소비를 그 카드 한 장에 몰아 쓴다고 가정하고
  전월실적 조건 충족 여부를 판단합니다 (카드 총 사용액 = 입력한 소비 합계).
- **카드 조합 추천**: 카테고리마다 가장 유리한 카드에 소비를 배정하고, 그 카드에 실제로
  배정된 금액만으로 전월실적 조건을 다시 판정합니다. 조건을 못 채우는 카드는 자동으로
  제외되고 다음으로 유리한 카드에 재배정되며, 연회비를 감당 못 하는(순혜택이 음수인)
  카드도 조합에서 빠집니다. "최대 카드 수"를 늘려도 실제로는 그보다 적은 장수만
  추천될 수 있습니다 (순혜택이 나오는 카드만 포함하기 때문). "카드 수별 총 순혜택 비교"
  표로 몇 장까지가 실익이 있는지 확인할 수 있습니다.
- 이 최적화는 완전탐색이 아니라 탐욕적(greedy) 배정 + 손실 카드 제거 방식이라
  이론상 최적이 아닐 수 있지만, 카드 수가 적어 실용적으로는 충분히 좋은 조합을 찾습니다.
